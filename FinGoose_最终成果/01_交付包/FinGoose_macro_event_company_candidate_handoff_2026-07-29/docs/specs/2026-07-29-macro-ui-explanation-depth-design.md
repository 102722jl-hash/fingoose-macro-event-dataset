# 宏观事件归因 UI 解释深度设计

## 目标

将当前偏编号和结论展示的宏观事件归因预览，调整为初学者也能跟随的中文证据链。每一步必须区分来源事实、市场观察、分析观点和事后验证，不将观点冒充为原始来源结论。

## 范围与边界

- 只增强项目内的本地只读预览 UI。
- 不修改 `outputs/fingoose_macro_event_attribution_v1/*.jsonl`。
- 不修改归因标签、置信度、复审结论或市场数值。
- 事件后第20个交易日数据可在内部审计页面显示，但必须明确标记“预测时不可见，仅供事后审计”。
- 原始市场、来源和样本编号仅作审计辅助信息。

## 内容结构

### 1. 宏观研报

每份可见研报展示：

- 中文标题、发布机构和发布时间。
- 基于归档 `summary` 和 `locator` 的中文内容摘要。
- 该证据在当时能支持什么判断。
- 证据不能单独证明什么，防止过度归因。
- 来源等级、原始编号和定位信息作为次要审计信息。

### 2. 数据截止

采用左右或上下分区的两组表格：

- **预测时可见**：事件前基准日和基准值、事件后第1个交易日、事件后第3个交易日的截止日、末值、变化和异常倍数。
- **预测时隐藏**：事件后第20个交易日的实际数据，只用于检验短期预测。

表格下方增加“为什么要分开”说明，解释前视偏差和隐藏标签泄露风险。

### 3. 期间描述

使用事件档案、事件传导节点和市场窗口生成三段中文摘要：

1. 事件在什么时间发生和公开。
2. 事件可能通过哪些经济渠道影响市场。
3. 前三个交易日内，各市场实际发生了什么。

此步只描述时序和观察，不在此处下最终因果结论。

### 4. 事实传导链

传导链按四段展示：

` 事件事实 -> 经济机制 -> 资产定价 -> 竞争解释 `

- 传导渠道卡片继续可点击，但强制使用深色背景、浅色文字和明确焦点状态，消除浏览器默认白色按钮。
- 每个渠道给出“为什么可能影响”的中文解释。
- 市场验证列出事件后第1、第3个交易日的实际变化和异常倍数。
- 竞争解释使用已有 `counterevidence` 的中文映射，并解释它为何会削弱事件归因。

### 5. 多市场趋势确认

表格从当前的方向对照扩展为：

- 市场中文名称。
- 完整观察窗口名称。
- 预期方向与实际方向。
- 实际变化幅度、异常倍数和强弱解读。
- 是否支持传导链及具体原因。

表格下方生成一段整体观点：是否形成跨资产一致性，哪个资产的证据最强，哪个可能受竞争因素影响。

### 6. 短期预测

展示五部分：

1. **核心观点**：目标资产、预测窗口、方向和置信度。
2. **判断依据**：引用宏观摘要、传导渠道和事件后第1/第3个交易日实测。
3. **分析观点**：解释为什么这些证据支持该方向，并明确这是证据加权归因，不是严格计量因果。
4. **风险与失效条件**：竞争解释、反向信号及何时应放弃原判断。
5. **事后验收**：单独显示事件后第20个交易日实际结果，标记预测是否方向正确，且不得倒灌为预测依据。

## 数据流

UI 继续只读加载 `samples.jsonl`、`events.jsonl`、`market-windows.jsonl`、`reviews.jsonl` 和 `sources.jsonl`。中文内容层根据现有 ID 查找事件、来源、行情和审核记录，然后在浏览器中构造展示模型。所有数值直接来自归档行情窗口，不在 UI 中另行改写。

## 错误与降级

- 来源摘要映射缺失时，显示中性中文说明和原始编号，不生成未经支持的事实。
- 行情窗口缺失时显示“未归档”，不显示 `undefined` 或虚构值。
- 分析观点与来源摘要使用不同视觉标记。
- 原始数据加载失败时保留中文错误信息。

## 验收标准

- 40 条样本均可打开，6 个推理步骤均有具体中文内容。
- 数据截止步骤同时展示可见 D1/D3 和隐藏 D20，且隐藏数据有明确警示。
- 趋势确认至少包含市场名、观察窗口、实际变化、异常倍数和解读。
- 短期预测包含判断依据、分析观点、风险、失效条件和事后验收。
- 传导机制按钮不再使用浏览器默认白色背景，文字对比度清晰。
- 桌面和 390px 宽度均无水平页面溢出。
- 页面无 JavaScript 异常，原始 JSONL 无变更。
