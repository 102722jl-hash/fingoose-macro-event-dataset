# FinGoose 完整传导路径 UI 设计

## 目标

将“动态传导链”从 111 条底层边的逐行清单，改为投研可读的完整路径视图。默认回答“具体事件如何影响经营、行业与公司”，并用独立标签页保留宏观资产验证路径。所有原始边、ID、审核状态和证据边界继续保留。

## 双标签结构

### 经营影响链（默认）

每个事件展示三条公司路径，直接复用现有 30 条 `event_company_mechanism_chains.jsonl`：

```text
具体事件锚点
→ 行为或政策变化
→ 可观测经营变量
→ 行业收入或成本变量
→ 公司业务暴露
→ 即时、短期、中期方向
→ 价格、混杂与反证验证
```

每张路径卡显示公司名称、所属行业、三期限方向、七个连续节点、经营指标及单位、生效条件、失效条件、事件证据和公司官方证据。技术 ID、主绑定和候选状态放入折叠详情。

路径按照冻结的 30 条事件—公司映射生成，不使用事件后价格选择公司或机制。

### 宏观市场链

将现有 `dynamic_edge_bindings.jsonl` 按事件锚点和图拓扑重组为：

```text
具体事件标题
→ 有方向的传导渠道
→ 中文经济变量（代码、单位、经济含义）
→ 资产及预期方向
```

同一渠道分叉到多个资产时分别形成完整路径。中间变量与同名资产不再显示成两个重复的大标题，而合并为一个市场指标节点；原始两条边保留在折叠技术详情中。

新增只读市场序列展示注册表，至少包含当前 111 条边涉及的全部序列：中文名称、代码、单位、经济含义和方向解释。未登记代码构建失败，不在浏览器中猜测名称。

宏观路径继续标记 `NEEDS_HUMAN_REVIEW`。现有机制证据仅达到事件级时，页面必须显示“事件级机制证据，未构成逐边确认”。

## 联动与交互

- 点击时间线节点后，两类路径都优先筛选该节点锚定的链；没有直接绑定时显示全部并提示原因。
- 标签使用分段控制，默认选择“经营影响链”。
- 经营路径卡默认展开机制主干，证据、条件和技术详情可折叠。
- 宏观路径默认展示中文完整路径，原始边 ID、节点 ID、置信度和审核理由折叠。
- 公司路径中的公司名称可联动下方公司详情。
- 不再在主视图显示 `event-01-shock`、`event-01-intermediate-*` 等技术字符串。

## 数据投影

`build_ui_bundle()` 新增两类投影字段：

- `operating_transmission_paths`：由每个事件的三条公司机制链组成。
- `macro_transmission_paths`：由原始宏观边按拓扑合并形成完整路径。

原有 `transmission_paths` 保留为技术血缘，不改变上游数据文件。宏观路径重组必须检测孤立边、重复边和循环；无法形成完整路径的边进入 `unresolved_macro_edges`，不得静默丢弃。

## 验收

- 十个事件默认均显示三条连续七层经营影响链。
- event-01 必须分别显示达安基因检测需求链、上海机场旅客吞吐量链和中国国航航空客流链。
- 宏观标签页不得出现 `SP500 → SP500`、`DCOILWTICO → DCOILWTICO` 形式的重复展示。
- 所有市场代码均有中文名称、单位和经济含义。
- 111 条原始边全部被完整路径或 `unresolved_macro_edges` 可追溯覆盖。
- 时间线节点选择、标签切换、公司联动和证据链接正常。
- 桌面和 390px 移动端无横向溢出或文本遮挡。
- `formal_ready=false`、`sha_gate=DEFERRED`、`NEEDS_HUMAN_REVIEW` 保持不变。
