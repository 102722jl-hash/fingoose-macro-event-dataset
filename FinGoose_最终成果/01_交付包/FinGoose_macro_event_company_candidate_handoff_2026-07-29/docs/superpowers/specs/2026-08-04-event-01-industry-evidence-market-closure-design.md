# FinGoose event-01 行业证据与行情闭环设计

## 1. 目标与范围

本轮只将 `event-01` 建设为八行业高质量纵向样板，不自动扩展其余九个事件，也不把候选结论晋升为正式结论。

样板覆盖以下八个互斥行业候选：

| 影响层级 | 行业 |
|---|---|
| 直接影响 | 医药生物、交通运输、社会服务 |
| 二阶传导 | 商贸零售、传媒、石油石化 |
| 条件性影响 | 计算机、食品饮料 |

每个行业采用统一研究链：

```text
事件锚点
→ 具体行为或政策变化
→ 可观测驱动
→ 行业经营变量
→ 收入或成本变量
→ 即时、短期和中期方向
→ 行情验证
```

所有记录保持：

```text
PROPOSED
NEEDS_HUMAN_REVIEW
formal_ready=false
sha_gate=DEFERRED
```

## 2. 基线与隔离方式

现有行业候选层继续作为只读基线：

- 10 个事件；
- 77 条行业映射；
- 539 个机制节点；
- 30 条公司回接；
- 77 条完成状态均为 `OPEN`；
- 现有证据主要覆盖事件锚点；
- 现有驱动和市场窗口仍为 `DATA_PENDING`。

新增独立覆盖目录：

```text
work/event_01_industry_closure_v2_candidate/
```

该目录只保存 `event-01` 的八条增强记录及其原始来源。UI 构建时按稳定 `event_industry_mapping_id` 将覆盖层合并到现有 77 条基线中。未涉及的 69 条行业记录不得发生语义变化。

覆盖目录包含：

```text
event_industry_mappings.jsonl
industry_mechanism_chains.jsonl
industry_evidence.jsonl
industry_driver_registry.jsonl
industry_driver_observations.jsonl
industry_market_windows.jsonl
industry_completion_report.jsonl
industry_source_fetches.jsonl
raw/evidence/
raw/market/
validation_report.json
manifest.json
```

`raw/evidence/` 保存网页正文或可合法保存的结构化响应；`raw/market/` 保存行情和驱动变量原始响应。`industry_source_fetches.jsonl` 保存请求 URL、参数、抓取时间、响应类型、保存路径、许可状态、成功或失败状态及失败原因。SHA 不作为本轮验收门禁。

## 3. 七步机制链

每条行业映射必须包含七个顺序节点，共八条链、56 个节点。节点不能使用“事件冲击”“全球需求渠道”等无法独立解释的抽象占位词。

### 3.1 节点字段

每个节点至少包含：

```text
mechanism_node_id
event_industry_mapping_id
step_number
step_type
statement_zh
statement_class
occurred_at_or_period
evidence_ids
premise_node_ids
condition_zh
invalidation_zh
status
```

`statement_class` 只允许：

- `SOURCE_FACT`：来源直接支持的客观事实；
- `CALCULATED_FACT`：由保存的原始数据和公式得到的计算事实；
- `RESEARCH_INFERENCE`：由前置事实推导出的研究判断。

### 3.2 事实与推断边界

`SOURCE_FACT` 必须具有原文引文、定位符、发布时间、首次公开时间、来源链接和用途边界。标题不能替代正文。

`CALCULATED_FACT` 必须保存输入序列、实际交易日、公式、输出值和数据来源。

`RESEARCH_INFERENCE` 必须引用前置事实或计算事实 ID，并记录成立条件、失效条件、竞争解释和反证。生成性文字不得写入引文字段，也不得登记为独立证据。

每条行业链至少具备事件锚点、行为变化、可观测驱动和经营变量四类事实支点。无法取得事实支点时保持 `EVIDENCE_PENDING`，不得用推测补齐。

### 3.3 交通运输示例

```text
WHO 宣布 COVID-19 构成全球大流行                         SOURCE_FACT
→ 多国实施旅行限制                                      SOURCE_FACT
→ 2020 年 3 月全球航空 RPK 同比下降 52.9%               SOURCE_FACT
→ 航空客流、客座率和机场吞吐量下降                       SOURCE_FACT
→ 客运收入下降、固定成本摊薄压力上升                      RESEARCH_INFERENCE
→ 即时负面、短期负面、中期混合                            RESEARCH_INFERENCE
→ 申万交通运输相对沪深300的固定窗口表现                   CALCULATED_FACT
```

## 4. 证据体系

### 4.1 来源等级

| 等级 | 范围 | 用途 |
|---|---|---|
| A | 政府、监管机构、国际组织、交易所 | 事件、政策、监管和官方统计事实 |
| B | 行业协会、公司公告、公司年报及其他一手行业材料 | 经营变量和业务暴露事实 |
| C | 权威媒体或可追溯数据服务 | 补充时序或交叉验证，不单独支撑关键结论 |
| D | 研究解释 | 不计作独立证据，只能作为 `RESEARCH_INFERENCE` |

### 4.2 时间用途边界

事件发生前或当时已公开且可用于预测的信息标记为 `PREDICTION_VISIBLE`。事件后发布、用于验证机制的数据标记为 `VERIFICATION_ONLY`。后见资料不得进入预测可见证据集合。

每条证据至少包含：

```text
evidence_id
source_tier
publisher
title
published_at
first_public_at
accessed_at
canonical_url
quote_zh_or_original
evidence_locator
usage_boundary
supports_node_ids
raw_snapshot_path
fetch_status
```

### 4.3 event-01 首批来源范围

优先核验并保存以下来源正文：

- WHO：全球大流行事件锚点；
- IATA：2020 年 3 月航空客运量和 RPK 变化；
- UNWTO：全球旅行限制覆盖情况；
- 中国民航局：航班、旅客运输量和行业运行情况；
- 国家药监局：新冠检测试剂应急审批；
- 国务院、国家卫健委：诊疗方案中的核酸检测要求；
- 国家统计局、工业和信息化部、行业主管部门：零售、餐饮、软件服务及其他经营驱动；
- 可复现且许可状态明确的行情或行业数据服务。

来源正文不可稳定取得时，记录检索范围和失败原因，状态保持 `EVIDENCE_PENDING`。

## 5. 驱动变量

每条行业映射登记一个主驱动，最多一个次驱动。驱动选择基于事件前行业机制，不允许根据事件后走势选择。

初始驱动方向如下：

| 行业 | 主驱动候选 |
|---|---|
| 医药生物 | 检测试剂获批数量、核酸检测需求或诊疗量 |
| 交通运输 | 航空 RPK、民航旅客运输量或机场吞吐量 |
| 社会服务 | 旅行限制覆盖、旅游人次或酒店入住率 |
| 商贸零售 | 社会消费品零售、线下客流或相关零售分项 |
| 传媒 | 影院营业率、观影人次或票房 |
| 石油石化 | WTI 价格、原油需求预测或商业库存 |
| 计算机 | 在线办公、云服务使用量或软件业务收入 |
| 食品饮料 | 餐饮收入、家庭消费和渠道销售结构 |

驱动数据保留原始单位、频率、时区、统计周期和发布日期。月频或周频数据不得伪装成日频，也不得无说明地插值或前向填充。图表可将低频观测画为离散点。

## 6. 行情与窗口

### 6.1 基准选择

`event-01` 使用事件日有效的申万分类版本 `SW2014`。每个行业使用事件日有效的申万一级行业指数，市场基准使用沪深300。

行情来源按以下顺序回退：

```text
申万事件日有效行业指数
→ 可复现的公开行情接口或许可数据库
→ 事件发生前已上市且预先登记的行业 ETF 代理
→ DATA_PENDING
```

ETF 必须在事件前确定行业匹配关系和有效期，不允许根据事件后表现挑选。无法取得合规数据时保持 `DATA_PENDING`，不得补零。

### 6.2 T0 对齐

事件首次公开时间统一转换为 `Asia/Shanghai`。若信息在 A 股交易日收盘前公开，`T0` 为当日；若在收盘后、非交易日或节假日公开，`T0` 为下一交易日。最终 `T0` 必须由带时间定位的来源确定，不能仅凭事件日期推断。

行业指数和沪深300必须使用相同的实际交易日期。保存：

- `T-20` 至 `D20` 连续交易日序列；
- `T-1、T0、D1、D3、D5、D20、M3` 固定观测点；
- 各点日期和指数绝对值；
- 相对 `T-1` 的收益率；
- 相对沪深300收益；
- 公式、输入值和缺失原因。

### 6.3 图表口径

行业详情默认绘制：

- 左轴：申万行业指数，`T-1=100`；
- 左轴：沪深300，`T-1=100`；
- 右轴：主驱动变量，保留原始单位。

用户可以切换原始值和归一化值。事件锚点及后续关键节点用竖线标注。事件总览使用收益矩阵比较八个行业，不在同一详情图中堆叠八条行业曲线。

## 7. 混杂、竞争解释与反证

每条行业映射保存：

```text
confounder_event
affected_window
mechanism_overlap
severity
alternative_explanation
counterevidence
attribution_limit
evidence_ids
```

`severity` 只允许：

```text
CLEAN
MINOR
MATERIAL
DOMINANT
UNRESOLVED
```

`event-01` 至少核验以下竞争因素：

- 中国国内疫情和管控早于 WHO 全球大流行定性，部分影响可能已提前计价；
- 沙特与俄罗斯油价战可能主导石油石化窗口；
- 全球美元流动性紧张和权益市场抛售可能主导短期行情；
- 美联储紧急政策响应改变金融条件和风险偏好；
- 各国旅行限制、影院停业和本地管控生效时间不同；
- 医药生物内部同时存在检测受益和常规诊疗受损。

`CLEAN/MINOR` 可进入主要候选样本；`MATERIAL/DOMINANT/UNRESOLVED` 只进入挑战集。经营变量支持而行情不支持时，记录“市场验证不一致”，不自动推翻机制。只有价格同向而没有机制证据时，不得补写行业影响。

## 8. UI 联动

在现有公司影响页面中加载行业覆盖层，保留左侧十事件导航。选择 `event-01` 后，右侧依次展示：

1. 具体事件名称、发生时间、首次公开时间、阶段和官方锚点；
2. 直接影响、二阶传导、条件性影响三个互斥分组及全部八个行业；
3. 当前行业的七步机制链；
4. 行业指数、沪深300和主驱动图表及固定窗口表；
5. 混杂、竞争解释、反证、归因边界和公司回接。

八个行业始终可见。选择行业只切换详情，不隐藏其他行业分支。

每个机制节点显示事实类型。`SOURCE_FACT` 和 `CALCULATED_FACT` 可展开原文、定位符、公式及直达链接；`RESEARCH_INFERENCE` 可展开前提、条件、失效条件和反证。

若行情或驱动缺失，UI 展示缺失原因、已尝试来源和 `DATA_PENDING` 状态，不绘制空白图，不把缺失值显示为零。没有公司样本时显示“行业机制已建立，当前尚未配置公司样本”。技术 ID、接口参数和审核状态放入折叠技术详情。

桌面端使用横向七步阅读；390px 移动端改为纵向机制流。全页面标题、图例、状态、错误提示和说明均使用中文。

## 9. 错误处理

- 网络失败、反爬页面、空正文和响应结构变化必须写入抓取记录；
- 页面标题不能在正文缺失时替代证据；
- 来源时间只能由页面或响应中的时间字段验证，不能从当前节点时间复制；
- 行情代码、分类版本或有效期无法确认时禁止回退到名称猜测；
- 低频驱动数据不得伪装成日频；
- 任何失败只产生明确的 `EVIDENCE_PENDING`、`DATA_PENDING` 或 `OPEN`，不生成替代事实。

## 10. 完成门禁

单条行业映射只有同时满足以下条件才能标记为 `CANDIDATE_COMPLETE`：

1. 锚点来自已验证时间线节点；
2. 七步机制链完整，事实与推断边界清楚；
3. 事件、行为、驱动和经营变量四类事实支点完整；
4. 三个期限均有方向，或使用 `UNKNOWN + ABSTAIN` 明确拒答；
5. 行业、沪深300、驱动数据和固定窗口可复算；
6. 混杂、竞争解释、反证及归因边界已登记；
7. 证据原文、定位符、链接和用途边界完整；
8. 结论保持待人工审核，不写入 `CONFIRMED`。

不满足任一条件时保持 `OPEN`，并在 `industry_completion_report.jsonl` 中列出具体阻塞项。

## 11. 测试与验收

### 11.1 数据测试

- 验证八个稳定映射 ID 和 56 个机制节点完整覆盖；
- 验证三个行业层级互斥；
- 验证事实节点具有来源，推断节点具有前提和条件；
- 验证证据链接、引文、定位符、发布时间和用途边界；
- 验证事件后信息不会进入 `PREDICTION_VISIBLE`；
- 验证申万历史版本、指数代码、ETF 有效期和预先选择依据；
- 验证行业与沪深300使用共同交易日；
- 逐项复算绝对值、收益率、归一化值和相对收益；
- 验证缺失值不转换为零，拒答不转换为方向；
- 验证挑战样本不进入干净归因集合；
- 验证覆盖层合并后其余 69 条行业记录不发生语义变化。

### 11.2 UI 测试

- 验证八个行业同时可见并可独立选择；
- 验证行业选择联动机制链、证据、行情、混杂和公司样本；
- 验证事实来源和直达链接可访问；
- 验证有数据时图表非空，缺数据时显示明确状态；
- 验证长引文、七步链和图例在桌面及 390px 移动端无溢出和遮挡；
- 验证控制台无运行时错误。

## 12. 交付边界

本轮交付是 `event-01` 的八行业高质量候选样板、原始抓取材料、验证报告和同一 UI 的联动展示。它不是正式发布版，不包含人工最终签署，也不触发 SHA 发布门禁。

样板通过用户和人工审核后，才为其余九个事件编写批量扩展计划。扩展阶段复用相同 Schema、抓取接口、门禁和 UI，不直接复制 `event-01` 的行业机制文字。
