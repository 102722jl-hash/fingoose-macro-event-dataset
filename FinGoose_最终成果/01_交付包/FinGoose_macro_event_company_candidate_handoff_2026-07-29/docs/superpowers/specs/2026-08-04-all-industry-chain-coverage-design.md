# FinGoose 全行业板块链覆盖与完整度展示设计

## 目标

修正当前“行业板块链仅展示已选行业”的行为，使单个事件下全部受影响行业始终可见，并将行业内容是否完整拆解为可核对的数据门禁。UI 展示完整不得被误解为证据、驱动或行情已经完整。

本次只调整独立行业研究层及其 UI 投影，不覆盖公司层数据，不改变冻结的 77 条事件—行业映射，也不把任何候选状态晋升为 CONFIRMED。

## 已确认展示方案

采用“全量分层总览 + 点选详情”。

每个事件的行业区同时展示三个互斥层级：

- CORE_DIRECT：直接影响。
- SECOND_ORDER：二阶传导。
- CONDITIONAL：条件性影响。

三个层级默认全部展开。行业卡片始终显示当前事件候选池中的全部行业。点击行业只改变高亮、详情和公司筛选，不改变全行业分支数量。

“行业板块链”标签默认展示当前事件的全部行业分支，不再使用 state.industryMappingId 过滤列表。每条分支先显示紧凑机制摘要：

事件事实 → 行为或政策变化 → 可观测驱动 → 行业经营变量 → 收入/成本变量 → 三期限方向 → 价格、混杂与反证验证

点击分支后，在行业详情区展示该行业的完整七步链、证据、驱动、行情和公司样本。其他行业分支继续保留在总览中。

## 内容完整度模型

每个行业分支必须覆盖以下研究字段：

1. 具体事件锚点、发生时间和首次公开时间。
2. 行为或政策变化。
3. 可观测驱动变量。
4. 行业经营变量。
5. 行业收入或成本变量。
6. 即时、短期和中期方向。
7. 生效条件与失效条件。
8. 混杂、竞争解释与反证。
9. 行业指数、沪深300及固定行情窗口。
10. 关联公司业务暴露样本。

机制节点按以下类型显示：

- SOURCE_FACT：必须有原文、定位符、首次公开时间和直达链接。
- RESEARCH_INFERENCE：必须记录支持证据、适用条件、失效条件和反证。
- VERIFICATION_PROTOCOL：必须说明验证数据、混杂规则和拒答边界。
- 缺少上述字段时保持待补状态，不允许用事件锚点证据替代整条机制链证据。

行业卡片不显示模糊的总体完成百分比，而显示四项可复核门禁：

- 机制证据 X/Y：Y 为需要支持证据的机制节点数，X 为已具备有效证据引用的节点数。
- 驱动数据：AVAILABLE / DATA_PENDING / NOT_DISCLOSED_AFTER_SEARCH。
- 行情窗口：AVAILABLE / PARTIAL / DATA_PENDING。
- 公司样本：已连接公司数量；零家公司时显示“公司样本待补”。

## 数据接口

继续保留现有六个行业 JSONL。增强内容写入底层数据，不由 UI 临时推测。

### industry_mechanism_chains.jsonl

每个节点继续保留 node_id、node_type、claim_kind、statement_zh 和 evidence_ids。节点证据缺失时 evidence_ids 保持空数组，并由完成报告产生明确阻塞项。

### industry_completion_report.jsonl

每条映射新增 gate_statuses，包含 mechanism_evidence、driver_data、market_window 和 company_sample。

每条映射同时新增 evidence_coverage，包含 required_node_count、evidenced_node_count 和 missing_node_ids。

completion_status 继续使用 CANDIDATE_COMPLETE / OPEN。任一必需门禁未关闭时保持 OPEN。

### UI bundle

UI bundle 继续按 event_industry_mapping_id 连接映射、机制链、证据、驱动、行情、完成报告和公司样本，不复制或覆盖公司层记录。

## 交互规则

1. 切换事件时显示该事件全部行业，并默认高亮第一条直接影响行业。
2. 切换行业层级不隐藏其他层级，只滚动或聚焦到对应分组。
3. 点击行业卡或行业链分支时，只更新 industryMappingId、详情和公司筛选。
4. 点击时间线节点时，行业分支显示锚点匹配状态，但不隐藏不匹配行业；当前十事件行业池均绑定各自已验证主锚点。
5. 无公司样本时不显示其他行业公司详情。
6. 行情缺失时显示数据可用性审计、缺口代码和禁止补零说明。
7. 技术 ID、底层绑定和完成阻塞项放在折叠技术详情中。

## 错误与缺失处理

- 缺机制证据：显示缺失节点名称和 MECHANISM_SUPPORT_EVIDENCE_INCOMPLETE。
- 缺驱动数据：显示数据源、频率、单位和 DATA_PENDING；未知内容不得推测。
- 缺行业或沪深300行情：保持空序列和空固定窗口，不绘制虚假折线。
- 缺公司样本：行业仍显示，并标记“公司样本待补”。
- 来源只有标题而无正文：不得计入有效机制证据。
- 事件后材料：只能标记 VERIFICATION_ONLY，不得计入预测可见证据。

## 验收标准

- 十个事件的行业分支数量分别为：
  - event-01：3 / 3 / 2
  - event-02：4 / 3 / 1
  - event-03：3 / 3 / 2
  - event-04：4 / 2 / 2
  - event-05：2 / 3 / 2
  - event-06：1 / 4 / 2
  - event-07：1 / 3 / 3
  - event-08：2 / 3 / 2
  - event-09：3 / 3 / 2
  - event-10：4 / 3 / 2
- event-01 的行业板块链同时显示全部 8 条行业分支。
- 选择任一行业后，全行业分支数量保持不变。
- 每张行业卡显示四项完整度门禁。
- 七步详情区分来源事实、研究推断和验证协议。
- 无证据、无行情和无公司样本状态均有明确说明。
- 桌面端与 390px 移动端无横向页面溢出、文本遮挡或控制台错误。
- 保持 PROPOSED / NEEDS_HUMAN_REVIEW / formal_ready=false / sha_gate=DEFERRED。

## 非目标

- 本次 UI 与数据门禁改造不自动补齐 77 条机制证据。
- 不从事件后行情反推行业选择或方向。
- 不以 ETF 自动替代缺失的申万一级指数。
- 不改变公司候选数量、公司 dossier 或公司价格窗口。
