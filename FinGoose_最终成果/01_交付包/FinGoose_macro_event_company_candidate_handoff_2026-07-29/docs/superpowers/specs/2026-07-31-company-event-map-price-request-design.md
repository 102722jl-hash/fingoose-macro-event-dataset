# FinGoose 公司事件映射与 A 股行情采购设计

日期：2026-07-31

## 1. 目标与边界

建立一份在查看事件后股价之前冻结的“事件—公司”候选清单，并生成可交给数据供应方执行的 A 股日行情采购单。首版覆盖 `event-01` 至 `event-10`，每个事件固定 5 家公司，共 50 条事件—公司记录。

本工作只新增独立候选目录，不修改现有 v2 数据、十事件页面、MySQL 表或既有 30 家候选记录。它不把候选公司自动晋升为正式归因样本；公司暴露证据、行情完整性、行业历史归属和混杂审核均通过后，才能进入正式评测。

## 2. 样本冻结方法

### 2.1 种子与扩充

- 复用 `data/company_candidate_v1/candidate_company_registry.jsonl` 中现有每事件 3 家、共 30 条候选作为种子。
- 每个事件补充 2 家，形成每事件 5 家、共 50 条固定记录。
- 同一上市公司可以出现在多个事件中，但每个 `event_id + ts_code` 只能出现一次。
- 不要求 50 条全部通过证据审核。无法证明事件前暴露的记录保留在拒绝或待补证台账中，不用事后表现更好的公司替换。

### 2.2 入选证据

公司只能依据事件首次公开前已经公开的材料入选，包括：定期报告、招股书、公司公告、交易所问询回复、公司官网业务资料及政府或监管机构文件。每条记录至少需要一项可定位的事件前证据，说明主营业务、收入来源、资产地域、成本投入或政策资格如何连接到具体传导路径。

禁止使用以下信息作为入选依据：事件发生后的股价、成交量、研报复盘、媒体事后赢家名单或任何未来财务数据。每条记录固定保存 `selected_at`、`selection_cutoff_at` 和 `price_selection_used=false`。

### 2.3 状态

- `VERIFIED`：事件前材料明确支持公司暴露关系，且证据有链接、发布日期、原文摘录和定位信息。
- `PARTIAL`：业务关系成立，但地域、收入占比或事件特异性只能部分确认。
- `PENDING`：候选逻辑合理，但尚无足够的事件前证据。
- `REJECTED`：主体、时间、业务或传导语义不符。

只有 `VERIFIED` 和经审核允许的 `PARTIAL` 可以计算候选公司窗口；`PENDING` 与 `REJECTED` 不进入正式归因分数。

## 3. 公司映射数据接口

`company_event_map.csv` 每行包含：

- `event_id`、`event_anchor_id`、`event_t0_date`；
- `ts_code`、公司中文名、交易所、上市与退市日期；
- `exposure_role`、`transmission_path_id`、预期影响方向；
- `selected_at`、`selection_cutoff_at`、`price_selection_used`；
- 暴露状态、审核人、审核时间、拒绝或缺口原因；
- 事件日申万一级行业代码、名称、版本、生效起止日期及行业指数代码；
- 公司证据 ID 列表和来源状态。

`company_exposure_evidence.jsonl` 保存来源 URL、发布机构、发布时间、访问时间、证据摘录、页码或段落定位、支持的事实、适用传导路径及证据等级。`rejected_candidates.jsonl` 保留被拒候选与完整理由，防止后续静默替换。

## 4. 行情采购范围

### 4.1 证券范围

供应方必须返回：

1. 冻结清单涉及的全部唯一 A 股证券；
2. 每家公司在事件日实际生效的申万一级行业指数；
3. 固定大盘基准中证全指；若供应方无法提供，则统一使用沪深 300，并在全数据集中采用同一替代基准，不按公司切换；
4. 交易日历、证券状态、除权除息和公司行动数据。

### 4.2 日期范围

每个事件—公司记录的请求区间为：

- 开始日：事件 `T0` 前 40 个自然月；
- 结束日：事件 `T0` 后 2 个自然月；
- 供应方按完整交易日返回，不只返回已预先计算的窗口点。

该区间覆盖 T-60、T-20、T-1、T0、D1、D3、D5、D20，并为事件前约三年的安慰剂窗口、停牌、节假日和 D20 前向收益预留缓冲。若公司在区间中途上市或退市，返回实际可得全历史并标记截断原因，不做填充。

`event-09` 的 A 股主锚固定为 `T0=2024-09-24`。其余事件的 T0 由项目事件锚点表逐项导出；盘后发布使用下一有效交易日作为证券 T0，并保留原始事件时刻与对齐依据。

### 4.3 日行情字段

个股至少提供：

- 证券代码、交易日期、交易所；
- 原始开盘、最高、最低、收盘、前收盘；
- 成交量、成交额、换手率；
- 累计复权因子、当日公司行动状态；
- 停牌、涨跌停、风险警示、上市和退市状态；
- 供应商数据版本、提取时间及字段口径。

指数至少提供原始收盘、前收盘、总回报指数或累计复权因子、指数代码、指数版本和交易日期。申万行业归属必须是事件日有效的历史归属，禁止使用 2026 年分类回填。

## 5. 价格、单位与收益口径

- 页面展示原始价格；收益计算使用后复权总回报价格。
- 可复算标准为 `total_return_price_t = raw_close_t * cumulative_adjustment_factor_t`，或供应方等价公式。供应方必须同时交付原始收盘价、当日累计因子及完整公式。
- 因子只包含在对应交易日已经生效的现金分红、送转、拆并股和配股等公司行动，不能把未来公司行动提前写入历史观测。
- 价格单位统一为“元/股”，成交量为“股”，成交额为“元”，换手率为“百分点”。同时保留供应商原单位和转换倍数。
- 不跨停牌日人工插值。窗口目标日无交易时，按预先规定的交易日历映射，并记录实际观测日、偏移和原因。

公司绝对收益：

`R_company(a,b) = TRP_b / TRP_a - 1`

相对行业收益：

`AR_industry(a,b) = R_company(a,b) - R_sw_l1(a,b)`

相对大盘收益：

`AR_market(a,b) = R_company(a,b) - R_broad_market(a,b)`

首版采用简单差额法，不在数据稀疏的种子集上估计公司特异性 beta。原始收益、行业相对收益和大盘相对收益必须同时输出。

## 6. 窗口与安慰剂

事件窗口保存 T-60、T-20、T-1、T0、D1、D3、D5、D20 的目标日期、实际交易日期、绝对价格和收益。核心前后比较至少包括：

- `T-1 → T0`；
- `T-1 → D1`；
- `T-1 → D3`；
- `T-1 → D5`；
- `T-1 → D20`；
- `T-20 → T-1` 作为事件前趋势背景。

安慰剂样本只从 T0 前三年的可交易历史生成。对每个真实窗口长度，在历史日期上使用相同交易日跨度计算收益，排除与真实事件窗口重叠的日期、停牌或不可复算日期，以及登记为 `MATERIAL` 或 `DOMINANT` 的其他重大事件窗口。输出真实收益在有效安慰剂分布中的经验分位数、有效样本数和排除数；有效样本不足 120 个时标记 `INSUFFICIENT_HISTORY`，不伪造分位数。

## 7. 混杂审核

每个事件—公司窗口登记公司公告、财报、业绩预告、分红、增发、回购、重大合同、监管处分、停复牌和行业级政策等竞争解释。混杂等级沿用 `CLEAN / MINOR / MATERIAL / DOMINANT / UNRESOLVED`。

`MATERIAL`、`DOMINANT` 和 `UNRESOLVED` 样本可以展示，但不得进入干净归因主分数。混杂判断必须有来源和时间，不允许仅凭价格形态推断。

## 8. 独立输出

所有新增文件写入 `work/company_event_map_v1_candidate/`：

- `company_event_map.csv`；
- `company_exposure_evidence.jsonl`；
- `rejected_candidates.jsonl`；
- `price_data_request.csv`；
- `data_dictionary.md`；
- `validation_report.json`；
- `summary.json`；
- `README.md`。

行情到货后另建数据目录，不把受许可限制的原始供应商数据写入公开页面或可再分发包。

## 9. 验收标准

- 恰有 10 个事件，每事件恰有 5 条固定记录，总计 50 条；
- 所有记录都有稳定 ID、明确传导路径、选择截止时间和 `price_selection_used=false`；
- 每个 `VERIFIED` 证据均早于或等于事件选择截止时间，且 URL、摘录和定位非空；
- `PENDING` 与 `REJECTED` 不进入正式窗口评分；
- 行业归属具备事件日有效区间，无法确认时保持 `UNKNOWN`；
- 行情采购单覆盖个股、历史行业指数、固定大盘指数、交易日历和公司行动；
- 原始收盘、累计因子和后复权总回报价格可逐行复算；
- D1、D3、D20、相对行业、相对大盘及安慰剂分位数可复算；
- 缺失、停牌、短上市历史和混杂不被零值或插值掩盖；
- `release_tier=CANDIDATE`、`formal_ready=false`，直至证据与行情完成双重审核。
