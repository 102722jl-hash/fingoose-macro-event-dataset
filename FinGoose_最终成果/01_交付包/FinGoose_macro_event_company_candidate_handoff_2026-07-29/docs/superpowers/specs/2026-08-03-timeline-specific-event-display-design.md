# FinGoose 时间线具体事件展示设计

## 目标

将十个事件共 50 个时间线节点从“阶段名 + 技术 ID + 英文事实”改为投研读者可直接理解的中文事件表达。主视图必须先回答“到底发生了什么”，技术字段下沉但不丢失。

## 方案选择

采用独立展示配置，不直接改写上游证据记录，也不在浏览器中临时翻译：

- 新增 `configs/company_impact_high_quality_v2/timeline_display_profiles.jsonl`。
- 每个 `fast_node_id` 唯一对应一条 `event_title_zh` 和 `event_summary_zh`。
- 标题必须包含明确主体和动作，例如“俄罗斯宣布对乌克兰开展‘特别军事行动’”，不得仅写“首次冲击”“政策响应”或技术 ID。
- 摘要用一至三句中文说明事实，不加入来源未支持的精确时间、因果判断或预测结论。
- 原始 `fact`、`fast_node_id`、`source_id`、时间精度和审核状态继续保留，便于复核。

相比直接修改 `timeline_nodes.jsonl`，该方案不会污染上游事实层；相比 JavaScript 规则生成，50 条中文表达可逐条审核、测试和复用。

## UI 结构

每个时间线节点按以下层级展示：

1. 主标题：具体中文事件标题。
2. 元数据：事件阶段、发生时间、时间精度。
3. 正文：中文事实摘要。
4. 状态区：证据状态、节点动作、官方证据链接。
5. 折叠技术详情：`fast_node_id`、原始英文事实、来源 ID、首次公开时间。

时间栏不再重复承担标题职责；移动端允许元数据换行，标题和正文不得被截断。

## 数据流与降级

`build_ui_bundle()` 读取时间线展示配置，按 `fast_node_id` 一对一合并到时间线节点。若节点缺少配置，构建阶段应失败并报告节点 ID，禁止悄悄回退为英文或技术 ID。配置不得覆盖证据状态、时间和来源。

## 验收

- 50 个时间线节点全部有非空中文标题与中文摘要。
- `fast_node_id` 一对一覆盖，无重复、无遗漏。
- 主标题不包含 `fast-event-*`，也不等于阶段名称。
- event-02 的五个节点均明确写出主体、动作和政策/冲突事实。
- 页面仍可通过节点联动传导链，官方证据链接可点击。
- 桌面和 390px 移动端无横向溢出、遮挡或文本截断。
- `formal_ready=false`、`sha_gate=DEFERRED` 和原始证据边界保持不变。
