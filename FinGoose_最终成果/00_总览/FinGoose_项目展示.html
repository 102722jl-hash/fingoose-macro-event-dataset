02路线演进：一路修正出来的最终版本

项目经历过多次路线推翻与重建。每个被放弃的路线，都对应一个明确被否决的理由。

v0.1 Canonical 100早期路线 · 已废弃

通用高质量样本的初始形态：只追求"样本看起来高质量"，没有把研究过程结构化。

为什么放弃：缺乏"宏观事件 → 行业 → 公司"的因果分层，无法回答"这个结论从哪条证据来"，可审计性不足——而可审计正是本项目的核心目标。

v0.1 五类 RLVR 试点方向修正

尝试用 RLVR（可验证奖励的强化学习）来训练金融推理。

为什么放弃：RLVR 需要一个能自动判定对错的奖励信号；而金融因果结论没有可靠的自动判分器，奖励机制反而会强化"自信但错误"的答案。与本项目"证据边界优先"的目标直接冲突。

v0.2 双轨数据集（含商品行情）部分保留

尝试「宏观事件 + 商品主连行情」双轨结构，商品行情派生数据保留在 data/commodity_market_v0_2。

为什么收窄：商品主连行情不能替代股票交易日历，双轨会让"事件 → 公司"的主线被行情细节稀释；因此把商品行情降级为辅助轨道，主线收敛为宏观事件研究。

v0.3 公开官方来源研究候选版演进中

确立 public_official_only 来源政策，禁用 Wind / 东方财富 / 新浪 / 同花顺 / 雪球。

为什么这样定：商业终端数据有许可限制、且外部无法复核；改为只用可公开复核的官方来源（政府、央行、交易所、公司公告），每条事实都要求"原文 + 定位 + URL"三要素，才能被第三方审计。

最终交接包（2026-07-29 打包 / 2026-08-06 更新）当前版本

统一为四层主线 + 统一 SFT：市场归因正式集 v1.0（formal_ready）+ 宏观事件公司影响候选集 v2 + 可审计推理链 + Skill 封装。

为什么收敛到这版：把"证据 → 推理 → 结论"显式建模成可校验的数据结构，并让训练产物由主数据确定性重建，从流程上消除"结论无据""数据漂移""信息泄漏"三类问题。

训练栈定型已验收

Qwen2.5-3B-Instruct · 4-bit NF4 QLoRA；dry-run 输出 ready=true，切分 124/16/17。

为什么选它：目标硬件是 RTX 4060 Laptop 8GB 显存，全量微调不可行、7B 也无法稳定运行；3B + 4-bit QLoRA 是在该硬件上唯一能稳定落地的基线配置。

03四层主线架构

每层都是上游的推导结果，且必须满足对应的门禁才允许进入下一层。

LAYER 1
宏观事件
10 个事件的结构化定义与时间线
→
LAYER 2
传导机制
事件 → 行业的时间线与传导链条
→
LAYER 3
行业影响
受益/受损方向与强度的可证伪判断
→
LAYER 4
公司影响 / 问答
公司级归因与事件研究问答
为什么不直接从宏观证据预测公司收入？ 项目最初的设想就是"用宏观证据直接预测公司利润"，但这条路径无法审计、也无法证伪。 改为四层主线后，每一步都必须显式给出中间机制（事件改变了什么变量 → 变量如何影响经营 → 经营如何落到财务）， 任何一环缺证据都会被门禁拦下，而不是被"跳步"成一个看起来很确定的结论。行业方向也不允许直接等同于公司方向。

04统一 SFT：四类任务

最终放弃 DPO / GRPO / RLVR，把全部监督信号统一成 157 条 SFT 样本。

任务类型样本数说明涉及层
EVENT_ANALYSIS10宏观事件本体分析Layer 1
INDUSTRY_IMPACT77事件对行业的影响方向与传导Layer 2 / 3
COMPANY_IMPACT30事件对公司的影响与归因Layer 4
EVENT_QA40事件研究问答Layer 4
合计157按事件划分切分：train 124（event-01~08）/ validation 16（event-09）/ test 17（event-10）
为什么把四类任务合成一个文件、用 split 字段区分？ 而不是拆成 train/val/test 三个文件： 因为四类任务都由同一个 event_id 派生，合并存放才能保证"同一事件的所有样本永远待在同一个 split"， 从结构上杜绝事件级数据泄漏；拆分文件反而容易让同一事件的样本散落各处。

05关键设计决策：为什么这样做，而不是别的做法

下表是项目中最关键的取舍。每一项都对应一个被明确放弃的替代方案，以及放弃它的技术理由。

决策点采用方案放弃的替代方案为什么这样做
训练范式 统一监督微调 SFT（HF/TRL messages） DPO / GRPO / RLVR 监督信号是"带证据边界的标准答案"，属于示范学习；金融因果无可靠自动判分器，RLVR 的奖励会把"自信但错误"的结论一起奖励。
数据切分 按 event_id 事件级切分（8/1/1） 按样本随机切分 同一事件的行业/公司/问答样本高度相关，随机切分会把 test 事件的上下文泄进 train，使评测虚高。
来源范围 仅 T1/T2 官方可复核来源 Wind / 东财 / 新浪 / 同花顺 / 雪球 商业终端有许可限制且外部不可复核；审计要求每条事实具备"原文 + 定位 + URL"，必须能被第三方独立验证。
不确定性 fail-closed：未达 IDENTIFIED 一律 ABSTAIN 直接给出方向/结论 金融因果很难被严格识别；宁可在证据不足时弃权，也不把"行情同步"写成"因果"。这是防止模型学会编造确定性的关键。
时间策略 双时钟：事前推理 / 事后验证分离 单一时间线用全部资料 防止把事后公告、事后行情回填成"事前可见事实"；否则训练数据里会出现未来信息泄漏。
证据表达 完整推理链存 metadata，messages 只放精简推导 扁平 evidence_ids 列表 扁平 ID 说不清"哪条证据支撑哪个节点、哪条路径支撑最终结论"；分层后既保证可审计，又保证可训练。
数据维护 确定性重建：同输入 → 相同 SHA-256 手工分别维护两份 JSONL 手工维护必然发生漂移；由主数据 + 配置确定性生成，才能让验证报告对文件做哈希绑定、让结果可复现。
训练配置 Qwen2.5-3B-Instruct · 4-bit NF4 QLoRA 全量微调 / 7B 基线 目标硬件为 RTX 4060 Laptop 8GB；全量微调装不下，7B 只能作实验配置、不能作为验收基线。
能力沉淀 封装为 Skill（统一 CLI + 严格闭环策略） 一次性脚本 / 只交文档 方法论要可复用、可版本化、可被新任务独立调用；Skill 能用前向测试验证"换个事件是否仍能跑通"。
发布状态 formal / candidate / 待人工复核 分级分离 统一标记"已完成" 结构完整 ≠ 证据完备 ≠ 因果成立；候选数据不得自动升级为正式发布，避免"看起来齐了就算合格"。
旧路线处理 全部归档，绝不删除 直接删除 / 原地覆盖 路线纠偏的过程本身就是成果的一部分；保留归档既能展示思路演进，也让任何结论都可回溯。

07可审计与门禁机制

这是项目最核心的方法论资产：没有证据不下结论，因果未识别一律弃权。

门禁状态

formal_ready达到正式集发布标准
candidate_ready候选集可达标，但未正式发布
CANDIDATE_SFT_ELIGIBLE可进入 SFT 候选
NEEDS_HUMAN_REVIEW需人工复核
ABSTAIN因果未识别 → 一律弃权

规范推理链 metadata v1

  • reasoning_chain：可追溯的推理步骤（节点 + 边）
  • evidence_registry：证据登记表
  • conclusion_lineage：结论谱系（结论从哪条证据来）
  • 节点状态：VERIFIED_SOURCE / EVIDENCE_MISSING / SUPPORTED_INFERENCE / INFERENCE_ONLY / CALCULATED_ONLY / CUTOFF_BLOCKED
  • 消息长度门禁：三条 messages 总字符数 ≤ 2000
为什么要做门禁，而不是"人工看一眼觉得没问题就发布"？ 因为可审计的对象必须能被机器重复校验。门禁把"合格"翻译成一组确定性的布尔条件 （四类任务齐全、事件不跨 split、无隐藏标签、无硬截断、外键可解析、SHA 一致）， 任何一条不满足就直接阻断发布——这样"是否合格"不依赖某个人的判断，也不会随版本漂移。
来源政策：仅允许公开官方来源（交易所、监管、官方统计、上市公司公告等）； 明确禁用 Wind、东方财富、新浪、同花顺、雪球等非公开/非官方来源。 受限数据边界记录在交付包的 restricted/ 目录。
